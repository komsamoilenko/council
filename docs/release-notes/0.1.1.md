# council 0.1.1

A corrective release. Everything 0.1.0 shipped is unchanged in scope; this release
fixes what a first real installation and a first real migration found, and makes a
version bump a mechanical act rather than a hazard.

The installed profile is now complete. 0.1.0 detected Codex by asking for
`--ignore-user-config` at the top level, where the Codex CLI rejects it, because
that flag and its two companions belong to the `exec` subcommand — the subcommand
the backend actually uses. Detection therefore marked a perfectly good Codex
unusable, and `machine.json` was written without its path. The same routine wrote
only five of the eight binaries its template names, so vendored ripgrep and the
Gemini API helper were missing too, and vault search refused every call. Detection
now probes the subcommand and records which isolation flags it accepts; the machine
document carries every key its template declares, including the write time, the
detected versions and the NOTICE acknowledgement; and `verify` compares the
installation against what detection found, reporting a usable CLI that the running
server calls unavailable as drift rather than passing in silence. An existing
installation is repaired by planning with no hosts and applying that plan.

Reading a vault no longer costs a process per directory. The survey used a
PowerShell attribute probe on every directory it walked, including the whole of
`.git`; on a vault of a few thousand directories `detect` took several minutes.
It now walks with `lstat`, which already reports the junctions and symbolic links
it must skip, and the attribute probe is kept for the places that decide a write.
The file count that guards against an accidentally broad vault root no longer counts
`.git`, `node_modules`, council's own job store or the ledger, and the report names
those exclusions with their counts instead of hiding them. A directory the account
cannot read is a warning naming the subtree, not a refusal — unless it is one of the
few paths the installer must read or write. Migration passes the large-vault
acknowledgement itself, since the vault it migrates was chosen by the installation
it is migrating, not by hand.

Migration recognises the registration it replaces by value. The Codex cut-over
previously accepted the previous table only when its path was spelled as a TOML
basic string with doubled separators — the spelling the installer's own emitter
produces. A table written by hand uses a literal string, which is the ordinary way
to write a Windows path in TOML, and the cut-over refused it. All three hosts now
compare the parsed value with the platform's own notion of file identity, so an
equivalent path in a different spelling is the same predecessor, and a table naming
a different server is still refused.

The personal-data scanner finishes on any file. A pathological input — eight
megabytes on a single line — made it exhaust the stack, so the gate saw a crash
instead of a finding. Reads and lines are bounded, and a file that cannot be scanned
is reported as a finding with its reason rather than passed over.

A release is now a two-file edit. The application version lives only in
`src/version.js`; the installer reads it instead of stating it in twenty-six places,
and the lint requires every version literal in the source, templates and documents
to equal it, so a stale claim fails a build rather than shipping. Two files must
agree, `src/version.js` and `package.json`, and both the Tier-0 suite and release
staging refuse to see them disagree. One rule came out of this work and applies
beyond it: a template that a released installer renders may only use the values
that installer already supplies, because an update renders the new release's
templates with the installer the user already has.

Windows remains the implemented platform, on the same terms as 0.1.0. Upgrading
from 0.1.0 needs no migration: `update` stages the new tree, runs the fast Tier-0
selection against it and promotes it, and the configuration schema is unchanged.
